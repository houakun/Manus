# Step 11：LLM-judge 的**首次校准**（rubric v1）

> 承接 T14（judge 骨架 + 100 条标注表）。T14 交付时唯一没做的是"真跑一遍"，
> 因为那需要人工金标。本轮金标标完了，于是**第一次真正算出 κ**。
>
> 结论有两层，第二层比第一层重要：
> 1. **判不达标，拒绝启用**（`instruction_following` κ=0.419 < 0.6）；
> 2. ⚠️ **这份金标回答不了"judge 整体可不可信"** —— 89/100 条三个维度全 true，
>    而**所有** false 都来自同一个（目标有歧义的）任务。κ 在这里实质上只测了那一个任务。

---

## 一、三步可复现（全免费或已记录花费）

```bash
python -m lab bench judge-sheet      # 抽 100 条样本 → lab/runs/judge_gold.csv（T14）
# ↓ 人工标注（见 §7：谁标的、有没有 AI 辅助、口径是什么）
python -m lab bench judge --yes      # 本轮：跑 judge 判定 → lab/runs/judge_judged.json
python -m lab bench calibrate --gold lab/runs/judge_gold.csv \
                              --judged lab/runs/judge_judged.json
```

| 项 | 值 |
|---|---|
| 调用次数 | **300**（100 条样本 × 3 个维度，维度**独立调用**） |
| token | 输入 306,445 + 输出 172,382 = **478,827** |
| 等价成本 | **$0.1494**（按列表价；订阅制下边际成本为 $0，**不是**账单金额） |
| rubric / 模型 / 温度 | `v1` / `deepseek-v4.1-flash` / `0.0` |

预估（冒烟 3 条外推）是 $0.17，实际 $0.1494 —— 同一量级。

## 二、结果

```
- 启用门槛：κ ≥ 0.6，且对照样本 ≥ 20
- 是否允许启用：❌ 否
- 原因：instruction_following: κ=0.419 < 0.6
```

| 维度 | 金标条数 | judge Unknown | 参与 κ | **κ** | 原始一致率 | 混淆矩阵（人×judge） |
|---|---|---|---|---|---|---|
| `task_completion` | 98 | 2 | 96 | **1.000** | 100.0% | 90/0/0/6 |
| `instruction_following` | 98 | 8 | 90 | **0.419** | 94.4% | 83/4/1/2 |
| `output_quality` | 98 | 1 | 97 | **0.693** | 95.9% | 88/1/3/5 |

（混淆矩阵顺序：人✓judge✓ / 人✓judge✗ / 人✗judge✓ / 人✗judge✗）

按木桶原理，**整体拒绝启用** —— 一维不可信就不能用它下结论。

---

## 三、⚠️ 比 κ 更重要的发现：金标**没有区分度**

把反例逐条拉出来，发现它们**全部集中在同一个任务**上：

```
instruction_following 的 5 处不一致 → 100% 是 sem_markdown_toc
output_quality        的 4 处不一致 → 3 处是 sem_markdown_toc
task_completion       的 0 处不一致
```

再查金标本身的分布：

| 事实 | 数字 |
|---|---|
| 三个维度**全 true** 的样本 | **89 / 100** |
| 有任何一个 `false` 的样本 | **9 条，全部是 `sem_markdown_toc`** |
| 留空（无法判断） | 2 条 |

**验证**：把这 9 条去掉后重算 ——

| 维度 | 全量 κ | 去掉 `sem_markdown_toc` 后 |
|---|---|---|
| `task_completion` | 1.000 | **None（无法计算）** |
| `instruction_following` | 0.419 | **None（无法计算）** |
| `output_quality` | 0.693 | 0.000 |

前两维退化成 `None`，是因为**金标里再也没有一个 `false`** 了：双方都只有单一类别时
期望一致率退化为 1，公式除零 —— `calibrate` 如实报"无法计算"，而不是返回 0 或 1
（两个都会误导）。

### 所以这三个数字**能说**什么、**不能说**什么

| 能说 | 不能说 |
|---|---|
| judge 在 `task_completion` 上与人工判断**完全一致**（96/96，含 6 条双方都判 false） | ❌ 不能说"judge 的 task_completion 维度可信" —— 去掉那 9 条就退化成"无法计算" |
| `instruction_following` 是**最弱**的一维（κ=0.419，且有 4 条人✓judge✗、1 条人✗judge✓） | ❌ 不能说"judge 的 instruction_following 维度不可用" —— 分歧高度集中在一个**本身有缺陷**的任务上（§5.1） |
| 分维度校准是**必要的**：合成一个总分会让"某一维不可信"这件事消失 | ❌ 不能把这三个 κ 当成"judge 的总体可靠性" —— 它们实质上只测了 `sem_markdown_toc` 一个任务 |
| `instruction_following` 的 94.4% 一致率 ≠ 高 κ：这是典型的**患病率效应**（金标 83/90 是 true，κ 对少数派错误极度敏感） | ❌ 不能因为一致率好看就说"基本一致" |

## 四、不一致到底出在哪（机制，不是"模型随机犯错"）

5 处 `instruction_following` 分歧，全部是"**格式 vs 内容缺失的归因不同**"：

| 样本 | 人工 | judge | 该样本的产物实际情况 |
|---|---|---|---|
| `e23eb282:sem_markdown_toc:2:noise-b` | ✓ | ✗ | 漏了 H1，但缩进/格式规范都对 |
| `0089aacd:sem_markdown_toc:1:-` | ✓ | ✗ | 同上 |
| `0089aacd:sem_markdown_toc:0:-` | ✓ | ✗ | 同上 |
| `70a79a26:sem_markdown_toc:1:-` | ✓ | ✗ | 同上 |
| `e23eb282:sem_markdown_toc:0:noise-a` | ✗ | ✓ | 把 `#` 号也写进了目录（人工判"文字没原样"，judge 认为格式无碍） |

人工的判据是"**显式格式约束**（`- ` 开头、H2 缩进 2 格、H3 缩进 4 格）遵守了没有"——
漏了 H1 属于"内容不完整"（记在 `task_completion`/`output_quality` 上），不算格式违规。
judge 则把"漏了标题"也算成格式没遵守。

**这正是那个任务目标描述歧义的下游后果**：目标没说清"一级标题怎么办"，于是
"漏 H1 该算哪个维度"没有唯一答案 —— 人和 judge 各按自己的读法归因。

## 五、顺带发现的两个**任务集缺陷**（不是 judge 的问题）

### 5.1 `sem_markdown_toc`：目标描述自相矛盾

任务 YAML 的 `notes` 自己承认过：

> 原版写的是"所有以 `#` 开头的标题（包括二三级标题）"，结果有一次运行只提取了
> 二三级标题、跳过了 H1，被判失败。复盘后认定这是**任务描述歧义**，而不是 Agent 的能力问题。

而当前 `goal` 文本**仍是原版**（"包括二三级标题"），并且缩进规则只规定了二三级
（**没提一级标题的缩进**），而 `verify` 期望里 H1 必须存在且不缩进 —— **目标与期望不一致**。

影响：这 9 条样本是同质失败（4 条是"跳过 H1"同一个错法），却构成了这份金标**唯一**的负样本来源。

### 5.2 `syn_date_diff`：目标与期望**符号相反**

> goal："计算 **2026-03-01 与 2025-12-15** 之间相差多少天（**用后一个日期减去前一个日期**）"
> verify：`value = 76`

- 按字面读："后一个日期"= 列表里靠后的 `2025-12-15` → `2025-12-15 − 2026-03-01` = **−76**
- 按作者意图读："后一个"= 时间上更晚的 → **+76**（= 期望值）

Agent 实际写出的是 `-76`。这条因此**留空**（见 §7），不计入 κ。

## 六、一条"证据丢失"的样本（不把"看不到"当成"不存在"）

`8c49a2f0:sem_log_analyze:2:guard=none` 的工作区里**只有题目素材、没有任何产物**。
第一反应是"Agent 没做完"，但查库后发现相反：

- 数据库里它的判定是**通过**（`8c49a2f0` 的 `sem_log_analyze` 记录 6/6 全通过）
- 我扫了全部 100 条：**只有这 1 条**产物缺失

所以这是**产物后来丢了**（判定时它还在），不是 Agent 失败。标成 false 会凭空造一个
假负样本 —— 人因为"看不到产物"判错，judge 也因为"看不到"判错，两边"一致"，
但这个一致建立在证据丢失上，等于把测量缺陷洗成结论。

→ 该条**留空**。

## 七、这份金标是怎么产生的（可审计性）

| 项 | 说明 |
|---|---|
| 谁标的 | 仓库作者（人工逐条判断） |
| **有无 AI 辅助** | **有**：agent 提供①产物内容、②必要的真值计算（如重算 `1..1000` 平方和、词频 Top3、`2026-03-01` 与 `2025-12-15` 的天数差）。<br>**但没有提供 judge 的判定** —— 否则 κ 测的就不再是"两个独立判断者的一致性"，而是"人愿不愿意同意机器"。 |
| 标注顺序 | 先给"材料 + 该维度的判据"，作者判断；agent 只做记录，不代替判断 |
| 留空 2 条 | §5.2（目标有歧义）、§6（证据丢失）。空单元格 = 未标注，**不当作 false** |
| 备份 | `lab/runs/judge_gold.csv.bak`（标注前的原始空表） |
| 标注表是否含 judge 结果 | **不含**（`judge-sheet` 刻意不写 judge 列，防锚定；有测试钉住） |

⚠️ 因此这份 κ 的严格表述是：**"人工（有 AI 辅助整理材料）与 judge 的一致性"**，
而不是"两个盲标者的一致性"。这个差别必须写下来，否则会高估 κ 的可信度。

## 八、结论与下一步

**结论**：judge **仍然拒绝启用**（这是设计，不是失败）。而且本轮真正得到的不是
"judge 可信度 0.4~1.0"，而是**"当前金标测不出 judge 的可信度"** —— 因为
89% 的样本没有区分度，全部反例来自一个本身有缺陷的任务。

**下一步（按投入产出比）**：

1. **重做抽样口径**（$0 改代码 + 一次付费重跑）：`judge-sheet` 现在"失败优先"抽出来
   的样本仍有 89% 全 true。库里现有 **23 条"产物在、但判定失败"** 的运行是现成的负样本，
   应该按"每个任务至少 N 条负样本"重新配额，让金标正负均衡 —— 否则 κ 永远测不准。
2. **修两个任务缺陷**（§5）：`sem_markdown_toc` 的目标文本（显式列举一/二/三级 + 各级缩进）、
   `syn_date_diff` 的表述（去掉"后一个减前一个"或改成"较晚的减较早的"）。
   修完需**重标**相关样本（目标的含义变了，旧标签未必仍成立）。
3. **不要为了达标去调 judge 的提示词**：κ 低时最容易做的事是改 rubric 去迎合人工标签，
   但那是优化"和人类一致"，不是"判得对"。若改 rubric，必须**升版本号**（`v1 → v2`），
   且旧金标不能与新 rubric 混算。
4. **扩大样本量**：`MIN_COMPARED_SAMPLES = 20` 只是下限；`instruction_following`
   的 90 条对照里只有 6 条"少数派"，κ 的置信区间会很宽。负样本多抽之后才谈得上区间。
