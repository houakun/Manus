# 任务集歧义 lint（T4 / 审计 §4.10）

> 工具：`python -m lab bench validate`（**不花钱**，已进 CI）
> 结论：22 个任务里 **1 个**被标（4 条路径）—— 而且它是**有价值的假阳性**，下面写清了原因。

---

## 一、它检查什么

判定器要检查的**每一个路径**，在 `goal`（给 Agent 看的题面）里提到过吗？

- 提到 → 不报；
- 没提到 → **warning**（不是错误，**不改变通过/失败**）；
- 比较方式：完整路径或最后一段文件名任一提及即可（题面写 `TOC.md` 也算说清楚了）。

## 二、为什么值得一条 lint（真实事故）

`sem_markdown_toc` 曾因"判定器要求保留 H1，而 `goal` 没说清"污染过**两次 A/B 实验**：
它在加固 2×2 里 4/9 失败，三种错法（留下 `##` 标记 / 漏 H1 / 缩进错）。

危险的地方不在于失败本身，而在于**它的失败看起来像模型能力问题**：
当时的报告里"加固让成功率 -8.3pt"完全由这一个任务的 3 次运行决定，
而根因是题面歧义（后来进一步诊断成能力边界，见
`docs/step6-followup-purpose-and-readpath.md` §1）。

所以这条 lint 的目标很窄：**让"题面没说清"在跑评测之前就可见**。

## 三、当前结果（22 个任务）

```
任务集自检：22/22 通过
⚠️  1 个任务的判定路径没在 goal 里说清（题面歧义）：这类失败看起来像模型能力问题，其实是题目没说清
```

唯一被标的任务是 **`syn_rename_files`**（批量重命名文件后缀）：

```
⚠ 歧义: 判定器检查 `/home/ubuntu/docs/a.md`，但 goal 里没提到它（`a.md`）—— 题面可能歧义
⚠ 歧义: 判定器检查 `/home/ubuntu/docs/b.md`，但 goal 里没提到它（`b.md`）—— 题面可能歧义
⚠ 歧义: 判定器检查 `/home/ubuntu/docs/a.txt`，但 goal 里没提到它（`a.txt`）—— 题面可能歧义
⚠ 歧义: 判定器检查 `/home/ubuntu/docs/b.txt`，但 goal 里没提到它（`b.txt`）—— 题面可能歧义
```

### 3.1 这是**假阳性**，原因写清楚

该任务的题面是"把 `/home/ubuntu/docs` 下的 `.txt` 批量改成 `.md`"——
**它是规则型任务**：具体文件名由 fixtures 决定，题面**不应该**把它们写死
（写死了反而变成"逐文件指令"，失去"批量"的意义）。

也就是说：**规则型任务的判定路径不必出现在 goal 里**，因为"规则"本身就足以推出路径。
lint 无法区分"规则型"和"点题型"，所以它只能出 warning —— 这正是设计意图：
**它负责让人看一眼，不负责下结论。**

### 3.2 什么情况才是真的该修

- 题面**没有**给出规则，但判定器要求某个具体路径（例如"生成 TOC.md"但题面只说"生成目录"）；
- 题面给了规则但**规则与判定路径矛盾**（例如题面说"输出到 out/"，判定器查 `/home/ubuntu/out.json`）。

这两种情况 lint 都会报，而它们值得改题面（不是改 lint）。

## 四、已知限制（连同结果一起读）

| 限制 | 影响 |
|---|---|
| 只比对**文件名/完整路径的字符串出现**，不理解语义 | 规则型任务会被误报（当前唯一一例） |
| 不检查 `goal` 里的**其他**歧义（格式、边界、顺序） | 它只覆盖"路径没说清"这一类 |
| 只在 `validate` 时跑，不阻断评测 | 这是刻意的：warning 不该变成门禁，否则会有人去改 lint 而不是改题面 |
| 不检查 `exec_script` 型检查（没有 path 字段） | CI 归因任务用的就是这种，它们靠 `fixture_authenticity` 兜 |

## 五、怎么跑

```bash
cd mooc-manus
.venv/Scripts/python.exe -m lab bench validate          # 22 个任务全跑（含三步自检 + 同义反复 + 歧义 lint）
```

输出里每个被标任务的 `⚠ 歧义:` 行就是 lint 结果；顶部会给出被标任务数。
