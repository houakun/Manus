# Step 15：rubric `v2 → v3` —— 收窄"命名"，也是**第一次跨过门禁**

> 承接 Step 14（v1 → v2：把边界写进提示词，IF κ 0.208 → 0.556，但 OQ 0.978 → 0.842）。
> 之后 `bench audit-labels` 把 v2 剩余的偏离**逐条列出来**：**18 条里 11 条是同一个形状** ——
> **某个字段的"值"写错了**（典型 `diagnosis.json` 的 `"file": "XXXXXXXX"`），
> 而 judge 把"值错"读成了"命名没按要求"。
>
> §5.4 当时就把这个诊断写下来了（**在做实验之前**）："judge 的读法**在 rubric 文本上有依据** ——
> 描述里写着「格式/路径/**命名**等显式约束」，而 `"file": "XXXXXXXX"` 看起来正是一个名字写错了。"
>
> 本篇是照着那份**预注册**的诊断改的：v3 把"命名"的范围收窄。

## 一、v3 改了什么（只动 IF / OQ 两个描述）

| 维度 | v2 | **v3** |
|---|---|---|
| `instruction_following` | "…结构/字段名/表头顺序对不对…**不要判断内容对不对**…" | "…结构/**键名**/表头顺序对不对…**任何字段的「值」写错都算内容问题**（包括那个字段装的就是文件名、符号名、测试名）—— 值错一律属于 `output_quality`。**这一维只看形式，不读值的内容。**" |
| `output_quality` | "…只判内容，不判路径/命名…" | "…数值对不对、文字是不是事实、**字段的「值」对不对**…只判内容，不判形式…" |

一句话：**v2 说"内容错不算 IF"，v3 进一步说"连'字段里装的名字'的值错也属于内容"**。

## 三、这个结果该怎么读（比数字重要）

### 3.1 它是**第一次跨过门禁**，但"跨过"不等于"可信"

- ✅ 三个维度都 ≥ 0.6（最低的 OQ 是 0.912，离门槛很远）；
- ⚠️ **但金标是"AI 给结论 + 你复核"**（Step 13 §7 已写明它**不是盲标**）→ 所以这个 `✅ 是`
  的含义是"**judge 与 {你+agent} 的判断一致**"，**不是** "judge 与独立人类一致"。
  要让这个 `✅` 站得住，**唯一**的办法是让一位标注者在不看 agent 结论的前提下重标一遍。

### 3.2 v3 **不是**全面更好：它用 OQ 换了 IF

- IF：0.556 → **1.000**（偏离 11 → **0**）
- OQ：0.842 → 0.912（**但仍低于 v1 的 0.978**）
- 也就是说：**v1 的 OQ 最好、v3 的 IF 最好** —— 三轮下来没有一版在所有维度上都最优。
  但总分歧从 **33 → 4** 是压倒性的，所以 v3 整体最好。

### 3.3 "一轮比一轮高"这件事必须被记下来

三次改动（v1→v2→v3）**每一次都让 κ 上升**，而且**最后一次刚好跨过门槛** ——
这个形状本身就值得警惕：《step13 §6.3》明确禁止"为达标去调 rubric"。

本项目的防伪措施是三条，逐条对照：

| 措施 | 执行情况 |
|---|---|
| 改动必须是**预注册的**（先写下诊断，再改） | ✅ v2 的边界写在 `judge-labeling-guide.md`（Step 14 之前）；v3 的"命名"诊断写在 §5.4（Step 15 之前） |
| **两边都比**（不能只看目标维度） | ✅ 每轮都列了三个维度；v3 的 OQ 只涨到 0.912（**仍低于 v1**），没有被藏起来 |
| **不达标也不许改**（要有拒绝的能力） | ✅ v1/v2 都如实报了"拒绝启用" |

> 但要说实话：**这三条挡得住"作弊"，挡不住"过拟合到这份金标"**。
> 最硬的检验仍然是 3.1 那条 —— 换一份独立标注的金标，看 v3 还灵不灵。

## 四、顺带抓到并修掉的一个真 bug

用 v3 跑完 `calibrate`，报告头写的是 **`rubric v2`** —— 因为报告用的是**当前默认版本**
（模块常量），而不是"**产生这批判定的那个版本**"。

这直接破坏"跨版本金标不得混算"的可审计性：报告头是判断"这批数据是哪个版本跑的"的**唯一入口**。

**修法**：`bench calibrate` 从判定文件的 `__meta__.rubric_version` 里读版本，传给 `calibrate()`；
`calibrate(..., rubric_version=...)` 新增该参数（不传则回落到当前生效版本，保持向后兼容）。
修完验证：三个臂的报告头分别是 `v1` / `v2` / `v3` ✅。

## 五、v3 剩下的 4 条偏离（都在 OQ，不在 IF）

| 模式 | 条数 | 样本 |
|---|---|---|
| `OQ` 规则=false、judge=true | 3 | `sem_sqlite_report:wrong_solution`（内容×1）、`syn_rename_files:wrong_solution`（形状×4）、`syn_rename_files:empty`（形状×5） |
| `OQ` 规则=true、judge=false | 1 | `ci_regex_escape:1`（判定器**全过**） |

前 3 条是"**形状坏了，judge 认为内容没问题**"；后 1 条相反。
它们没有再聚成一个"同一形状"的模式（不像 v2 的 11 条那样集中），
所以**没有指向下一处明确的规格缺口** —— 到此为止继续改提示词就变成"照着这几条改"了，
那正是要避免的。

## 六、复现

  LAB_JUDGE_RUBRIC=$v python -m lab bench judge \

## 七、结论与建议

1. **v3 在门禁口径下达标**（0.978 / 1.000 / 0.912），且总分歧 33 → 4；
2. **但"达标"建立在非独立金标上** → 它只能算 **provisional**：judge 可以用来当
   **辅助信号**（本来也不进确定性基线），**不可以**当成"已验证可靠的裁判"；
3. **下一步真正该做的是"换一份独立金标复测"** —— 其它任何动作（继续调提示词、
   加采样、换模型）都在"不知道 v3 是不是只在拟合这份金标"的前提下进行。
